# Submission checklist

## Repository

- [ ] Create the GitHub repository as **public**.
- [ ] Push the `main` branch and confirm CI is green.
- [ ] Open the repository in a logged-out/incognito window.
- [ ] Follow the README from a fresh clone: install, test, `feedverdict eval`,
      and one live run.
- [ ] Confirm no `.env`, API key, local SQLite database, or screen-recording file
      is committed.
- [ ] Replace any remaining placeholders and check that README links render.

## Video

- [ ] Keep the final duration below 3:00 (target 2:45).
- [ ] Show code actually running, including one live run and one labelled fault
      scenario.
- [ ] Explain why provider time—not HTTP receipt time—detects silent stale data.
- [ ] Explain why one fresh source is not allowed to update canonical state.
- [ ] Set access to “anyone with the link can view.”
- [ ] Test the link in a logged-out/incognito window.

## Email

- [ ] Reply to the original assessment email only once with exactly the GitHub
      and video links.
- [ ] Open both links one final time from the sent draft.
- [ ] Send before end of day Monday 17 August 2026.
